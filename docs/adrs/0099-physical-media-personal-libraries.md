# 0099. Physical Media personal libraries

**Date:** 2026-08-17
**Status:** Accepted

## Context

[ADR 0098](0098-inventory-scoped-local-library-catalog-filters.md) unlocked restricted Local (Navidrome) search/queue via inventory grants: playlist-scoped “burned CDs” and a full-library Library Card, stocked on a Thrift Store. That model treated local access as a flat coupon list. Operators now want **collectible Physical Media** (records, CDs, cassettes, 45s) that map 1:1 onto prefix-named Navidrome playlists, plus a separate consumable Library Card.

Constraints:

- Shopping session state is plugin-namespaced, so a new plugin cannot join Item Shops rotation without a core refactor. Physical Media stays in `plugin-item-shops` as an extraction-ready `localLibrary/` module.
- [ADR 0089](0089-metadata-source-content-browse.md) still forbids user-facing browse-by-playlist. Listeners must not receive Navidrome playlist ids.
- [ADR 0086](0086-metadata-search-result-cache.md) keys search as `metadata:search:v1:{sourceId}:{query}` with **no user or playlist component**. Local search is playlist-filtered per user; opting Local into that cache without adding scope to the key would leak one user’s filtered results to another.

## Decision

1. **Derivation:** Physical Media items are derived from Navidrome playlists whose names start with `[CD]`, `[LP]`, `[TAPE]`, or `[45]` when Item Shops `derivePrefixedPlaylistsAsPhysicalMedia` is on (default). Optionally, every Navidrome album may also derive when `deriveAlbumsAsPhysicalMedia` is on — see [ADR 0110](0110-catalog-mode-physical-media.md). `shortId` is `pm-<playlistId>` for playlists and `pm-al-<albumId>` for albums. Default price/rarity come from `songCount`. `ItemDefinition.description` is the playlist `comment` when that field is non-empty after trim; otherwise the canned line `A {format} from the Record Store. Queue any track on it for the rest of the session.` Config is **overrides only** (`physicalMediaOverrides`); operators do not author full item definitions for records.
2. **Rebuild:** Derived catalog rebuilds on plugin `register`, `MEDIA_BRIDGE_STATUS_CHANGED`, config change, and the admin `refreshLocalLibrary` action (which also invalidates the daemon playlist/cover caches).
3. **Redemption:** `LocalLibraryGrant.redemption` is `"durable" | "perQueue"`. Physical Media is durable (unlimited queueing from that playlist for the game session). Library Card is `perQueue`. `pickGrantToConsume` never returns a durable grant. Holdings still strip on `GAME_SESSION_ENDED` (session-scoped durability).
4. **Shops:** Thrift Store is replaced by **Record Store** (`record-store`, Physical Media + Scratched CD, `distinctOffers`, omitted from the effective catalog when no records derive) and **Public Library** (`public-library`, Library Card). Default `enabledShopIds` is computed from the **effective** catalog so dynamically contributed shops are included in new rooms. Existing rooms with `thrift-store` in `enabledShopIds` lose that shop until they enable `record-store`.
5. **Client items:** `EFFECTIVE_METADATA_SOURCES` (and INIT) include `myMedia: { mediaKey, name, icon?, imageUrl?, artworkFrame? }[]` for the caller’s held playlist-scoped grants. `mediaKey` is the item `shortId`. Add-to-Queue CatalogBrowse gains a **Physical Media** root tab (`RootKind: "media"`).
6. **BROWSE_MEDIA_ITEM:** The handler accepts only `mediaKey`. The server resolves it to a Navidrome playlist id from the **caller’s held grants** (`Plugin.resolvePhysicalMediaItem`) and then calls `listPlaylistTracks`. Never trust a client-supplied playlist id.
7. **Cache-key guardrail:** Do **not** opt Local search into the ADR 0086 `metadata:search:v1:{sourceId}:{query}` cache unless the key also includes the playlist-scope (or user) component. Local search remains uncached until that is designed.
8. **Cover art by URL, not by payload:** The daemon's `getPlaylistCoverArt` RPC returns data URIs; when the adapter requests `variants: ["sm", "lg"]` the daemon fetches Navidrome `getCoverArt` at **384px** (rows) and **1200px** (Now Playing). A missing `variants` param still returns today's flat `Record<id, dataUri>` at 640px so a stale DJ Mac pack degrades instead of failing. `PluginAPI.getLocalPlaylistArtwork` re-hosts each variant in the room image store under a content-hashed id (`pl-cover-<playlistId>-<hash>` for the row size, `…-<hash>-lg` for the large size) and hands back `{ imageUrl, imageUrlLarge }` URLs. Only those URLs reach the wire, as `ItemDefinition.imageUrl` / `imageUrlLarge`, `ShopOffer.*`, `PhysicalMediaItem.*`, and `pluginData["item-shops"].physicalMediaFrame`. `imageUrl` takes precedence over `icon` everywhere items render; the Lucide icon stays as the fallback for records with no art. Per-track `mapSong` covers stay at 640px (Now Playing fallback when a record has no playlist cover). Content hashing means re-derivation is idempotent and new art busts the old URL.
9. **Surface bridge failures instead of empty records:** `fetchLocalPlaylistTracks` returns `{ ok: true; tracks } | { ok: false; error }` so `browseMediaItem` can distinguish "record is empty" from "daemon never answered" and return a `BROWSE_MEDIA_ITEM_FAILURE` telling the listener to ask the host to reconnect the DJ Mac. Client browse suppresses "No tracks found" while in the failure state. `listLocalPlaylistTracks` keeps its empty-array-on-error shape for callers that cannot act on the reason.
10. **Collection surfaces the item, not the slots:** The Collection area of the game-state inventory renders only when the caller holds a collection item, without empty slot placeholders (unlike `inventory` — [ADR 0100](0100-dual-inventory-slot-pools.md)). Each Physical Media row that opts into `detailView` opens an in-tab Game State detail subroute (large art + track list with preview / Add) — [ADR 0104](0104-game-state-item-detail-subroute.md). Durable records have no "use" action, so Details takes that secondary-action slot. Add to Queue → Browse → Physical Media remains available from the queue modal itself; Collection no longer deep-links via `EDIT_QUEUE.browseMediaKey` as the primary path.
11. **Artwork frames:** Derived Physical Media carries an optional `artworkFrame` presentation token (`"jewel-case" | "record-jacket" | "die-cut-jacket" | "cassette-case"`) on `ItemDefinition`, `ShopOffer`, and `PhysicalMediaItem`. The value is mapped from the Navidrome playlist prefix (`[CD]` → jewel case, `[LP]` → record jacket, `[45]` → die-cut jacket, `[TAPE]` → cassette case) at derivation time only. It is **never** inferred from operator display-name or icon overrides (`physicalMediaOverrides` has no frame field). The web client renders CSS/SVG overlays when both `imageUrl` and `artworkFrame` are present (`FramedArtwork` with a named size preset: `row` / `track` / `feature` — `feature` prefers `imageUrlLarge`). The layout box is the physical object (square sleeves/jewel cases; portrait 70:110 cassette cases), square corners, drop-shadow. Shop offers, collection inventory, and Add to Queue → Physical Media (item list + track list) all go through `toPhysicalMediaArt` into this component. `PluginRegistry.listPhysicalMediaItems` / `resolvePhysicalMediaItem` parse frame tokens via `parseArtworkFrame` (the retired `"j-card"` alias maps to `"cassette-case"`).
12. **Now Playing, Queue, and Playlist sleeve (optional):** Item Shops public config `showPhysicalMediaFrameInNowPlaying` (default `false`) chooses sleeve/case vs unframed track album art in Now Playing, queue rows, and playlist history. When Item Shops is enabled, `augmentNowPlaying`, `augmentQueueBatch`, and `augmentPlaylistBatch` attach `pluginData["item-shops"].physicalMediaFrame` (`artworkFrame`, plus `imageUrl` / `imageUrlLarge` when the playlist has cover art) if the Local track belongs to a derived Physical Media playlist (via `checkLocalTrackPlaylistMembership` — no playlist id on the wire). Queue and playlist **wire** payloads run `PluginRegistry.augmentQueueItems` / `augmentPlaylistItems` at read time so Redis blobs stay unchanged. The client resolves the sleeve through `resolvePhysicalMediaArt` / `usePhysicalMediaArt` and renders `FramedArtwork` only when the toggle is on, so flipping it takes effect without waiting for the next track. If the record has no cover, or the cover URL fails to load, the track's album art fills the same frame. Room artwork override and Guess the Tune obscured artwork still win. Attribution is playlist membership, not “queued from the Physical Media tab,” so a Library Card play of a track that also lives on a held record still gets the sleeve.

### What remains from ADR 0098

Grant-on-item (`library` vs `playlist` scope), restricted-Local access via `grantMetadataSourceAccess`, invisible `playlistIds` filters on search/browse/getTrack, and the admin `listPlaylists` picker for extra config rows remain in force. §7 (“no client playlist vector”) is replaced by `myMedia` / `mediaKey` as specified above. Seeded Thrift Store SKUs and consume-on-queue for records are replaced by derivation + durable redemption.

## Consequences

- Collecting records uses the existing inventory/transfer/grant path; a later plugin extraction does not need a data migration if session-end still strips Item Shops items.
- Prefix typos silently yield no item; operators should watch derived-item count after refresh.
- Playlist cover art costs two Redis writes per record per derivation (384px row + 1200px feature), but keeps `USER_GAME_STATE` and shop payloads small. Track/album art in browse results still rides the wire as adapter-supplied urls. Changed artwork orphans the previous content-hashed keys until the room is deleted (`deleteRoomImages` is unimplemented); doubling variants doubles that drift.
- Art is fetched only for playlists that parse as Physical Media, and only when the bridge is linked; an unlinked bridge yields icon-only records rather than a failed refresh.
- Playlist membership cache is daemon-global (contents are user-independent). A future per-user playlist view would break that assumption.
